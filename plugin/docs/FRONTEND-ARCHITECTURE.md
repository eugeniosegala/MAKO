# MAKO Decky frontend code map

MAKO Decky's panel composes independently owned state and view modules. Keep profile persistence in the existing hooks and backend RPC boundary; settings components render those values and send changes through the supplied callbacks.

| Concern | Owner | Boundary |
| --- | --- | --- |
| Panel composition and modal entry points | `src/components/Content.tsx` | Wires installation, session, configuration, and status hooks to views. |
| Current game and selected editing profile | `src/hooks/useProfileSession.ts` | Selects the editor profile without changing the running game's profile. |
| Profile lists and matching | `src/hooks/useProfileManagement.ts` | Calls backend profile RPCs and synchronizes the selected profile. |
| Configuration loading and live status | `src/hooks/useMakoHooks.ts` | Reads backend state and supplies the current configuration. |
| Reopened panel layout | `src/hooks/panelSnapshot.ts` | Remembers what an installed panel last showed, per running app, so a remount starts from the same layout; see [the panel snapshot](#panel-snapshot). |
| Debounced configuration writes | `src/hooks/useProfileConfigWriter.ts` | Serializes and applies editor changes; controls should not create a second save queue. |
| Main feature grouping | `src/components/FeatureSettings.tsx` and `src/components/ModalityTabs.tsx` | Owns the settings tabs and their [focus navigation](#settings-navigation). |
| Feature controls | `src/components/FpsMultiplierControl.tsx`, `ScalingControl.tsx`, and `src/components/settings/` | Sends typed configuration changes through the editor callbacks. |
| Shader effect selection | `src/components/settings/shaders/EffectsChecklist.tsx` | Owns effect order, paging, Steam focus, and serialized live saves; `ShadersConfigurationGroup.tsx` owns the surrounding settings, custom file picker, catalog labels, and profile-keyed reset. `useMakoConfig()` reads the catalog with the profile; `Content.tsx` drains the existing save queue before add/refresh and guards against late profile reloads. |
| Flatpak setup | `src/components/FlatpaksModal.tsx` | Owns extension and application operations and their status display. |
| Native Remote Play controls | `src/components/RemotePlaySection.tsx` | Polls typed override status without overlapping requests, drains queued profile writes before mutations, rejects stale poll results, and refreshes the existing profile list after successful installation/removal. Groups the action, optional help, and compact status panel with shared section spacing; checking, working, unavailable, and recovery states stay visible when info is hidden. |
| Shared presentation | `src/components/MakoUi.tsx`, `ContentNotices.tsx`, and `RuntimeStatusCard.tsx` | Renders controls, notices, and status without persisting profile state. |

`ModelWarning.tsx` owns the single Lossless Scaling warning. `useModelFallback.ts` automatically replaces confirmed unavailable LSFG and LS1 selections with MAKO FG and MAKO Scaler through the ordinary profile writer. It edits only the current profile and power mode, retains a scoped explanation after the change, and leaves unknown inspection results and working selections alone. A failed save uses the writer’s existing reconciliation without an automatic retry loop. No manual model-switch action is required. LS1/LSFG compatibility warnings retain the optional update action. `ModelDropdown.tsx` uses Steam’s disabled menu items for unavailable LSFG and LS1 choices; MAKO choices and unrelated controls remain enabled. `ScalingControl.tsx` retains scaling controls and surface guidance without duplicating DLL/model warnings.

An unavailable inspector produces a quiet compatibility-unverified status notice for the selected Lossless Scaling models, including a missing or older RPC backend. Pending checks and model-free selections do not show it. Unknown results do not disable or rewrite a selection; confirmed failures retain the warning and fallback behavior above.

`StatusDisplay.tsx` keeps the Renderer status row readable when supplied status text is empty or whitespace: a ready row uses the localized installed label, and an unresolved row uses the localized checking label. Non-empty progress and failure messages remain authoritative. The Lossless Scaling row always labels the dependency as optional: a detected DLL shows a check and the installed label; an undetected DLL shows an X and the not-installed label. This row is informational and does not gate the editor. Advanced Details keeps the full detection result. These essential labels stay visible when R1 hides optional information, including after reopening the panel.

`useInstallationActions.ts` keeps the Renderer completion notice visible for at least three seconds, then waits for `Content.tsx` to refresh installation status before unlocking actions. The post-installation check replaces the previous update requirement before the notice closes, so a completed update cannot briefly offer the same update again.

`runtimeScalingUtils.ts` selects Live Status's scaling owner using the Renderer’s applied Scaling flag and active spatial work. An internal bridge display-size resize does not turn on Scaling or create a scaling-pending notice. Requested settings remain separate so enabling or disabling Scaling can still report a pending restart without misreporting the running feature.

## Settings navigation

The settings tabs use a three-column Steam focus grid with Frame Generation, Scaling, and Shaders on the first row, then Performance, Advanced, and Tweaks. The shared Image Processing header uses `MakoSectionHeader` for its divider and section spacing above the grid. The last activated tab is retained in local browser storage across panel reopenings and profile changes; missing, invalid or unavailable storage falls back to Frame-gen.

Directional handlers use each tab's Steam `navRef.TakeFocus()` handle to move controller focus within rows and columns, including in virtual-focus trees used during games. Keyboard navigation falls back to DOM focus when no Steam tree is available. Input is consumed only after a successful focus move; outer edges and failed moves remain owned by Steam navigation. Focus movement does not select a tab.

Tab names replace individual panel headings; panels keep accessible labels. `ConfigurationSection.tsx` renders selected groups directly in tabs while retaining the headers and collapsible controls for External Tools and Manual Overrides below the launch instructions.

`InfoVisibility.tsx` owns panel focus scrolling and R1 position restoration. Browser and Steam controller focus share one scrolling handler. The panel claims Steam descendant scroll ownership and cancels older Steam animations through `scrollTo` before placing the current target. Element checks work across Steam windows, and panel-local focus history supplies the previous control when virtual focus omits a browser related target. Paired browser/controller notifications retain one pending scroll; blur cancels stale requests without consuming controller input.

The tab grid uses `data-mako-focus-scroll="group"` to place the group's centre one-third of the way down its scroll viewport when focus enters from a preceding control in the same panel, leaving more room for the selected panel's controls. Panel DOM order supplies the entry direction. Placement respects the top edge and available scroll range. Navigation within the grid, entry from below or an unknown origin, and the first control focused on leaving the grid scroll only as needed. Pending entry positioning survives rapid moves within the grid but is cancelled when focus leaves or R1 restores its position.

Other ordinary settings centre on navigation; controls inside `data-mako-focus-scroll="nearest"` scroll only as needed to remain visible. The effects selector uses this policy and disables Steam's enclosing Field scroll-on-child-focus option, so moving between visible rows does not recenter the panel. Its controls own their focus outlines, clear stale hover on navigation, and ignore blur events from an older focus target. When the effects list collapses, `PanelFocusScrollContext` asks the panel to reveal its current controller target again after layout. The selector does not preserve an offscreen destination or restore stale browser focus. Focus scrolling is immediate so collapse cannot interrupt an unfinished reveal; Customize, Add, Refresh, and later controls use the same owner. Focus returning to the selector cancels pending collapse work.

## Profile state and configuration

`PowerProfileControls.tsx` renders the shared/native power-profile toggle and editing-set selector. `useMakoHooks.ts` retains the backend's resolved editing set and guards pending loads; `useProfileConfigWriter.ts` keys queued patches by both profile and power set, so a source change cannot move an old edit to the new set. `Content.tsx` routes editor reloads through the existing writer's queue drain: loading locks edits before flushing, then reads canonical state after every queued or in-flight save finishes. This keeps shared shader values current across manual power-set selection and automatic source changes. Failed-write reconciliation loads directly, without waiting on its own in-flight write. The toggle flushes pending edits before cloning or removing power sets. `useProfileSession.ts` refreshes the editor after a live game's confirmed AC/battery change.

## Panel snapshot

Decky remounts the panel on every open, and an empty first render jumps as the installation check, profile sync, configuration load, saved-profile list and Remote Play poll answer. `panelSnapshot.ts` remembers what an installed panel last showed in memory and `localStorage`, bound to the plugin build: installation versions, the saved-profile list and the Remote Play status, plus, for each of the eight most recent running apps (or none), the editing profile, that profile's settings and its last live-status reading. `Content.tsx` restores it on mount: the view kept for the app now running (or for none), with settings and live status only for that view's profile.

The snapshot is display-only. Every backend read still runs and replaces it; the first reload of the restored profile refreshes the settings in place, with edits locked as for any load, and any other load shows the loading row as before. Install, update and removal wait for the real installation check, Remote Play changes wait for a live status, and model fallbacks wait for the real configuration load and use live status alone; the status card and scaling controls only display the remembered reading until the first poll.

The snapshot is dropped when Decky unloads the plugin (update, reinstall, removal or reload) and before and after each Renderer install, update or removal, and a check that started before such a drop cannot write it. Only a successful check outside those actions writes it, and a verified missing Renderer clears it.

The schema source is `shared_config.py`; `src/config/generatedConfigSchema.ts` is generated. Decky's translation source is `defaults/i18n/`; `src/i18n/languages.json` is generated. Follow [testing](../../TESTING.md) after moving a component boundary, and preserve keyboard, gamepad, focus, selected-order, and profile-switch behavior in the focused frontend tests.

`FlatpaksModal.tsx` keeps each app's preparation toggle separate from extension availability. It joins the backend's current `runtime_version` with the existing extension-status response to show ready, missing, or unavailable status for prepared apps. A missing matching extension offers the existing install operation beside the app. Extension installation, update, and removal refresh both inventories without rewriting app overrides; operations are serialized while pending. Opening the modal performs discovery without installing missing branches.

Native Remote Play extends `useProfileSession.ts` with a backend-confirmed native-client session; it does not fabricate a local Steam app record. Sessions without an AppID follow the ordinary saved selection and use the existing power-source reload and write-queue behavior. The dropdown, rename, and delete controls stay locked, while Create Profile can save and select a named copy during a stream. Selection revisions reject polling replies sampled before the save completed. On stream exit the editor retains its selection; local-game exit follows the backend idle selection once (Default unless the override is enabled). `useProfileEditorModel.ts` reloads its catalog after override changes and runtime profile selection to keep the selectable profiles current. **Create Profile** uses the existing backend clone operation. Creation, capture, rename, and deletion drain queued writes before changing profile data, and selection drains them before persisting `current_profile` and loading the editor.

## Shader parameter editor

`ShadersConfigurationGroup.tsx` keeps unavailable shader actions as native disabled buttons with a muted neutral palette, including Delete when no custom effect is selected. They do not register a Steam navigation node or accept browser focus; enabled actions use Decky's `DialogButton`. This avoids Steam's deliberate suppression of the native disabled attribute and covers empty selections, missing actions, and operations in progress. The action rows stay in the panel's navigation order; only Add and Refresh share a horizontal focus group. An outer group would remember Add while Customize is disabled and could skip Customize after selecting effects.

`settings/shaders/ShaderParametersModal.tsx` owns the separate left-side shader editor. `Content.tsx` drains the ordinary profile writer before opening it, then fixes the popup to that profile. The panel stays inside Steam's modal safe area; its inner width wrapper and content form a bounded flex column, with a stationary header and independently scrolling controls. Fixed wrappers use non-scrolling clipping so focus cannot pan the panel. Header actions share the available width, override Steam's button minimum and content-box sizing, wrap translated labels, and leave room for focus outlines.

The editor claims Steam's descendant scroll ownership through `MakoFocusable`, preventing Field and controller smooth scrolling from competing with focus updates. Browser and virtual controller focus move only the owning controls/error scroll region, use its viewport scale, and cancel an older animation through `scrollTo` even when the latest control is already visible. The bordered controls area and focus scrolling share a 12 px inset to keep focused controls clear of its edges. No animation queue or idle polling is added. B is consumed before closing; B, Escape, Close, and explicit discard return through Decky's Quick Access tab, preserving its selected plugin and MAKO settings section.

The modal discovers compiler metadata once, combines edits for 350 ms, serializes writes, and drains pending work before closing, including edits made while a save is in flight. One persistent header status covers discovery, saving, completion, and unsaved failures. Saving starts when an edit is queued and stays visible until all queued writes finish and at least 500 ms have elapsed, including the debounce interval. This presentation timer never delays persistence or closing, is cancelled by a new edit or unmount, and yields immediately to save failures. The status never adds a footer or replaces a pending save with a success message. It reserves the translated completion message's height so ordinary save transitions do not resize the controls. Focused number fields commit before closing, switching effects, or hiding controls.

Each parameter keeps a 10 px gap between its slider and exact-value field, with 16 px between parameters for focus outlines. `shaderControls.ts` implements the shared [shader parameter editor contract](../../engine/docs/LAYER-CHAINING.md#shader-parameter-editor-contract) for FP32 presentation, slider steps, and exact-value input. Headings and fields use the same presentation; untouched fields never save a shortened display value back. Errors retain pending values for retry; explicit discard drops only unsaved changes. The backend validates every update against the discovered controls and rejects changed configuration identities. No parameter state is added to the shared renderer schema or local storage.

`ShaderParameterControls.tsx` presents consecutive compiler-declared colours in the same authored category as a four-column swatch grid. Selecting a swatch reveals only that colour's RGB/RGBA sliders and exact fields; controller focus alone does not select it. Swatch selection commits the focused numeric draft through the modal's existing owner before replacing controls. Swatches and the larger preview clamp only their displayed colour, preserving exact and out-of-range values. Reset still covers the complete effect, including colours whose controls are hidden, and preserves author-protected channels. Single colours keep their inline controls; category changes, intervening controls, and missing metadata retain the original ordering and scalar fallback. This presentation uses the existing metadata and adds no Nostalgia-specific rules or shader runtime work.
